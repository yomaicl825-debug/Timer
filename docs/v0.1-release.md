# Timer V0.1 · 本机试用版

发布日期：2026-09-28。项目使用 MIT 开源许可。

## 下载与安装

- Windows 安装版：下载 `Timer-0.1.0-preview-windows-setup.exe`，双击安装。
- Windows 便携版：下载 `Timer-0.1.0-preview-windows-portable.zip`，完整解压后运行 `study_timer.exe`。
- `SHA256SUMS.txt`：用于核对 Windows 文件完整性。
- `V0.1-release-notes.md`：本说明的离线副本。
- 发行页的 Source code：本版本源码，含 Android 工程、CloudBase 云函数、部署说明和测试。

本次将已验证的 Windows 0.1.0-preview 文件统一归档为 V0.1，安装包内部版本及文件名保持原样。安装包暂无商业代码签名，Windows 可能显示发布者未知。

## 已包含的功能

- 自定义任务名和任务累计时长；主窗口任务列表与个人主页入口。
- 沉浸式时区时钟、学习正数计时、番茄钟倒计时。
- 暂停、继续、结束、休息计时及手动开始下一轮。
- 历史记录归类、修改计入时长；每日、每周、每月统计及日历。
- 深浅主题、三种数字字体和时区选择。
- 本机 SQLite 数据保存。

## 当前限制

- 此 Windows 包仅在当前设备保存数据。邮箱登录和跨设备同步尚未启用。
- V0.1 尚无数据导出与恢复入口；清除应用数据前请保留本机数据。
- Android 源码和验证流程已包含，但公开 APK 需要配置项目专属的长期签名密钥。
- iPhone 版尚未发布；本发行页不包含 iOS 安装包。

## 下一步：CloudBase

1. 登录 [CloudBase 控制台](https://console.cloud.tencent.com/tcb)，按提示完成账号认证并创建 `timer` 环境。确认费用、额度与有效期后再开通。
2. 记录环境 ID 和地域；环境 ID 是公开配置，管理员密钥不要提交到 GitHub。
3. 按仓库 `docs/cloudbase-setup.md` 启用匹配客户端的邮箱登录，配置四个集合及私有规则，并部署 `timer-command` 云函数。
4. 在 GitHub 仓库 Actions 的 Variables 中添加 `CLOUDBASE_ENV`，值为环境 ID。
5. 完成双账号权限隔离、跨设备同步和并发计时现场测试后，重新构建支持云同步的安装包。当前包不会自动启用云端功能。

## 下一步：Android 公开安装包

1. 生成并安全备份项目专属的长期签名文件及密码；后续 APK 更新继续使用同一签名。
2. 打开仓库 Settings → Secrets and variables → Actions → New repository secret，配置：
   - `ANDROID_KEYSTORE_BASE64`：签名文件的 Base64 内容。
   - `ANDROID_STORE_PASSWORD`：签名文件密码。
   - `ANDROID_KEY_PASSWORD`：签名钥匙密码。
   - `ANDROID_KEY_ALIAS`：签名钥匙名称。
3. 使用仓库 `.github/workflows/release.yml` 构建、校验并发布后续版本。该流程由小写 `v` 开头的版本标签触发，当前 `V0.1` 归档不触发它。
4. 签名材料只存放在安全备份和 GitHub Secrets 中，不上传到公开源码或发行附件。

Android 可先发布本机记录版，再在云端验收完成后发布支持同步的更新。

## 后续版本规则

V0.1 归档后保留原版。改进在新的独立目录进行，默认依次命名 V0.2、V0.3 等；主版本号仅由用户确认增加。具体见源码内的 `docs/version-policy.md`。
